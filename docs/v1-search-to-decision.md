# Search to Decision [V1]: Intent, Grounding & Deterministic Ranking

> **Milestone 1 & 2 Architectural Article**<br>
> An educational reference implementation for understanding how an AI-powered search journey moves from natural language intent → dynamic query fan-out → multi-source retrieval → evidence aggregation → deterministic constraint evaluation → explainable ranking → grounded recommendations.

---

## 1. Overview

Traditional keyword search maps a user query directly to an index of links. In contrast, modern AI-assisted search pipelines orchestrate structured, multi-step search journeys:

```text
User Intent ──▶ Query Fan-Out ──▶ Multi-Source Retrieval ──▶ Grounded Evidence ──▶ Deterministic Constraints ──▶ Ranking ──▶ Grounded Recommendations
```

### Core Architecture Principles

> **"Agents reason; tools retrieve; deterministic code evaluates; evidence justifies."**

- **Intent Extraction**: Gemini parses natural language requests into structured multi-label intent classifications (`commercial`, `local_discovery`), identifying categories, reference locations, operating hour constraints, group sizes, hard criteria, and soft preferences.
- **Dynamic Query Fan-Out**: The query planner dynamically decomposes the user's intent into discrete retrieval tasks routed to **Google Places API (New)** (structured candidate data) and **Google Search Grounding** (qualitative web claims).
- **Candidate Normalization**: Raw records are deduplicated by unique Google Place IDs while preserving every retrieval occurrence across fan-out queries.
- **Evidence Aggregation & 3-Way Matrix**: Multi-source signals are unified into an explicit three-way evaluation matrix: `SUPPORTED` (verified positive), `NOT_SATISFIED` (explicit conflict), and `UNKNOWN` (neutral, unverified). Crucially: **`UNKNOWN != false`**.
- **Deterministic Ranking**: An additive scoring model evaluates hard points (+25), preferences (+10), proximity bonus (Haversine decay up to +12), and quality signals (+10 max) without allowing the LLM to override scoring.
- **Grounded Final Answer**: Gemini synthesizes grounded explanations and match rationales strictly for the deterministically ranked Top 3 candidates, with bounded resilience and fallback.

## 2. Run and Inspect It Yourself

You can execute and inspect the complete V1 Search to Decision pipeline locally in seconds.

### Local Setup & Launch

```bash
# 1. Clone repository and set up virtual environment
git clone https://github.com/hastimal/ai-search-journey-lab.git
cd ai-search-journey-lab
python3 -m venv .venv
source .venv/bin/activate

# 2. Install dependencies
pip install -e ".[dev]"

# 3. Configure API keys in .env
cp .env.example .env
# Edit .env to supply your GEMINI_API_KEY and GOOGLE_MAPS_API_KEY

# 4. Launch the Streamlit Journey Inspector
streamlit run src/ai_search_journey/app.py
```

*(Note: V1 runs strictly in-memory (`Session only`) with zero cloud database requirements. No BigQuery setup is required).*

### Test Scenario & Prompt

In the Streamlit Journey Inspector (or via the **Quick Demo Presets** dropdown), enter the standard discovery prompt:

```text
Find a coffee shop near Geekdom San Antonio for 6 people to work together, preferably quiet, and open after 8 PM.
```

Click **🚀 Run Search Journey**.

### What to Inspect in the UI

Open the **Search to Decision [V1]** tab and explore its five sub-tabs:

1. **🎯 Recommendations & Intent**:
   - **Static Map Preview**: Google Maps Static API preview with labeled markers (`A`, `B`, `C`) corresponding to the deterministically ranked Top 3 venues.
   - **Grounded Final Answer**: Synthesized prose with match rationales, verified signals, and explicit unverified assumptions.
   - **Ranked Top 3 Candidate Cards**: Distance, rating, score, and supported signals with source badges.
   - **Parsed Search Intent**: Extracted category, reference location, group size, and constraint list.
2. **🔀 Planner Query Fan-Out**: Inspect the distinct tool tasks generated by Gemini (`GOOGLE_PLACES` vs. `GOOGLE_SEARCH`), planner queries, goals, and executed search queries.
3. **📊 Constraint Matrix & Metrics**: View the complete candidate-by-constraint evaluation grid (`✓ SUPPORTED`, `? UNKNOWN`, `✗ NOT SATISFIED`) with multi-source provenance tags (`PLACES [F1]`, `SEARCH [F3]`).
4. **🔎 Evidence Inspector**: Examine claim-by-claim structured opening hours, review counts, web claims, and citations.
5. **🛠️ ADK Developer Trace**: Inspect the step-by-step execution timeline, wall-clock durations, and resilient model invocations.
